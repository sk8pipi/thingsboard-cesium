# 报警历史统计架构

> 状态：已批准并实现；最后更新：2026-09-07。
> 范围：报警趋势持久化、采集事务、历史聚合、权限、迁移与回退。

## 唯一数据源与边界
- alarm 是现存报警及生命周期状态的数据源；alarm_occurrence 是报警趋势的唯一历史统计依据。
- 每个 (tenant_id, alarm_id) 一条记录；created_time 和 customer_id 为创建时快照。
- severity 保持最后已知严重度；更新只改变分类，不增加总数。删除原报警后保留最后分类。
- 记录不包含完整详情和凭证；不向前端传输历史明细。
- 来源设备、客户和原报警没有历史表外键；只有租户外键 ON DELETE CASCADE，租户注销才清理相应历史。
- 设备换客户不搬动既有统计。客户注销后其历史仍归原客户 UUID，由租户管理员查看，新的客户不继承。

## 采集事务
- 生产创建入口为 create_or_update_active_alarm：新建分支插入 alarm 后同步插入 alarm_occurrence。
- 该函数的更新分支及 update_alarm 同步严重度；先保存原 row_count，保持原 API modified 语义。
- 唯一键用于重试和补录去重。相同 ID 持续更新不新增；解除后重新产生不同 ID 计为新报警。
- 报警确认、解除、分配、删除、TTL 清理不扣减历史总数。
- 同事务保证二者共同提交/回滚；采集失败会阻止本次报警创建，不能吞掉错误造成静默漏记。
- 不通过浏览器轮询、内存事件、定时扫描或规则链外部写入维护权威数量。
- 直接 SQL/DAO 绕过创建函数的历史导入必须走显式补录；当前生产入口均使用创建函数，测试中存在直接 save。

## 查询与权限
- 接口契约见 docs/api/alarm-statistics-api.md。
- TENANT_ADMIN 查询登录租户；CUSTOMER_USER 查询登录租户及历史 customer_id 快照，空客户拒绝。
- 不根据前端提供的 tenantId/customerId 放大范围；不 JOIN alarm、device 或 entity_alarm，以免删除导致历史丢失。
- 服务生成有界的7个日桶或24个小时桶；DAO按租户、客户及时间索引过滤并聚合，空桶补零。
- API不支持任意无限时间段或原始历史明细查询。响应 no-store。
- 数据库不可用/未迁移/缺少覆盖元数据返回503，不能用现存报警或零值降级。

## 时间及覆盖
- 时间基准为创建时间 createdTime，非 startTs/endTs/删除时间。
- Asia/Shanghai，sevenDays 包含当前自然日和前6天；twentyFourHours 包含当前小时和前23小时。
- 查询截至服务端 generatedAt（毫秒，包含该时刻）；SQL 上界为 generatedAt+1，不读未来记录。
- alarm_statistics_state 保存首次激活时刻；重复安装/迁移不推进该时刻。
- completeFrom 是可保证完整采集的起点；查询开始早于该时间时 historicalDataIncomplete=true。
- 补录只能恢复仍存在的记录。早先已删除的报警不得伪造恢复；补录严重度采用补录时最新值。
- 历史默认长期保留，但图表时间窗口正常滚动。无限保留会增长存储，需要持续容量评估。

## 安装、迁移与兼容
- schema-entities.sql 定义表和索引；schema-functions.sql 定义采集及元数据激活。新安装按现有安装顺序执行。
- 既有数据库普通启动不自动建表、不自动补录。脚本只生成供审核的SQL，实际执行须单独批准。
- scripts/alarm-trend/New-AlarmStatisticsMigration.ps1 从上述正式来源提取片段，避免维护第二套函数定义。
- 维护窗口暂停所有报警生产/删除和TTL，备份后在一个事务内锁定 alarm、建表、替换两函数、激活并去重补录。
- 全流程和手动命令见 docs/changes/alarm-trend-history/migration.md。
- 不改变现有报警列表API和部件ID；旧 pageSize 设置保留但趋势不再依赖分页。
- 部件复用原图表、刷新周期、过期请求保护；旧统计接口不作为自动回退。

## 回退
- 优先回退前端展示，保留采集及历史表；旧图表恢复后会重新受删除影响，必须明确告知。
- 若必须恢复旧创建函数，使用维护前数据库函数备份并暂停相关写入。历史表保留。
- 停采期间可能丢失已删除报警，重新启用后必须把该缺口视为不完整；不能保留原完整性声明掩盖停采。
- 任何实际回退、历史删除和业务数据迁移仍需要单独明确批准。

## 验收

并发、跨小时/午夜、空桶、客户租户隔离、租户注销、迁移重复执行与未迁移503。
