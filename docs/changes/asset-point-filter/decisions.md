# Cesium 大屏按资产显示点位决策记录

## DEC-001：沿用 ThingsBoard 实体身份与关系模型

- 状态：已批准
- 决策：资产使用 ThingsBoard Asset，传感器和摄像头继续使用 ThingsBoard Device UUID；通过实体关系解析归属，不复制点位或引入第二套资产设备绑定。
- 原因：保持地图点位、遥测订阅、权限校验和视频播放身份一致。

## DEC-002：首期只筛选 Cesium 点位

- 状态：已批准
- 决策：首期只影响 Cesium 中的传感器和监控点位，不联动设备统计、能耗和报警部件。
- 原因：避免不同业务部件的数据口径在未定义时被隐式改变。

## DEC-003：筛选条件是用户运行时状态

- 状态：已批准
- 决策：管理员模板仍保存完整点位集合；资产选择按用户和大屏保存在浏览器本地，不写回模板。
- 原因：同一租户大屏可被不同用户同时查看，不应互相覆盖筛选条件。

## DEC-004：使用标准 Contains 出向关系和直接关系 BFS

- 状态：已批准
- 决策：资产归属契约冻结为 `Asset --COMMON/Contains--> Asset/Device`；前端从所选资产开始逐资产查询直接出向关系，使用有限并发、访问资产去重和规模上限完成 BFS。
- 原因：标准关系接口会校验根实体及关系两端的读取权限；直接 BFS 能限制遍历路径，而复合递归查询只过滤结果、不限制途经的其他 `COMMON` 关系。

## DEC-005：现有 API 足够，首期不新增后端接口

- 状态：已批准
- 决策：分页调用当前权限范围的 AssetInfo 列表，并复用 `/api/relations` 直接关系查询；不修改数据库或后端控制器。
- 原因：当前约百级点位规模可控，新增聚合接口的公共契约、权限测试和缓存成本暂无必要。

## DEC-006：失败、空结果与竞态分开处理

- 状态：已批准
- 决策：成功解析且零设备显示空状态；请求失败保留上一份已成功筛选结果并显示错误；快速切换使用请求代次丢弃旧响应；本地保存资产已删除或无权限时才回退“全部资产”。
- 原因：不能把权限/API 故障伪装成资产确实没有点位，也不能让晚到响应覆盖用户最新选择。

## 已冻结实现契约

- 资产目录：租户管理员调用 `getTenantAssetInfoList`，客户用户用登录态 `customerId` 调用 `getCustomerAssetInfoList`，遍历全部分页并支持前端搜索。
- 用户入口：在运行态 `MapScreenTopBar` 动作区增加具名插槽，资产选择器不进入管理员模板动作配置。
- 本地键：按用户 ID 和 dashboard ID 隔离；“全部资产”不写入 Dashboard。
- 点位过滤：只在 `MapHome` 向 Cesium 传参前按 `point.entityId` 与 Device UUID 集合匹配。
- 弹窗：隐藏当前传感器时关闭并清空；隐藏当前摄像头时调用现有 `closeCameraPopup()`，由既有 watcher 释放直播与录像会话。
- 报警聚焦：只允许命中当前可见点位，避免重新打开已被筛选隐藏的设备。

## RIO

### Risks（风险）

- 关系存在环、重复边或历史脏数据，递归必须去重并设置安全边界。
- 大量资产逐级请求可能造成慢加载，应优先使用已有复合关系查询能力。
- 筛选隐藏正在播放的摄像头时若不主动清理，可能残留流会话或弹窗状态。
- 窄屏顶部栏空间有限，选择入口必须支持收纳或弹层。

### Impact（影响）

- 主要影响地图用户页、顶部栏、点位渲染和本地筛选状态。
- 可能扩展现有 Asset/Relation 前端 API 封装和专项测试。
- 只有在标准受权 API 不足时才考虑后端聚合接口。

### Options（选项）

- 方案 A：复用现有 Asset 与 Entity Relation API，在前端构建筛选集合。改动小，需验证权限和请求规模。
- 方案 B：新增后端聚合接口一次返回资产树和设备 UUID。性能与口径集中，但会新增公共接口及测试成本。
- 当前倾向：先验证方案 A，若不满足权限或规模要求再停止并提交方案 B 的契约评审。
