# Cesium 大屏多分辨率自适应决策记录

## DEC-001：采用安全画布混合适配

- 状态：已批准
- 日期：2026-08-31
- 决策人：用户与主 Agent
- 最终决定：Cesium 保持原生容器渲染；地图部件使用 1920×1080 基准安全画布、动态 GridStack 尺寸和容器响应式控件，不对整页使用 `transform: scale()`。
- Risks：动态 GridStack 参数可能发出 change；旧模板存在超过默认设计行数的可能；4K Cesium 像素量较大。
- Impact：只影响 Vue 3 地图前端和 Dashboard 内嵌模板配置；模板版本升级到 v6，但原 `x/y/w/h` 保持兼容；无 API、数据库和部署变化。
- Options：整页缩放实现更快但有模糊与拾取风险；横纵独立拉伸会造成部件变形；独立断点布局管理成本高，留作未来移动端需求。
- 回退：恢复固定 `cellHeight: 30`、`margin: 10` 和 v5 默认归一化即可；旧布局坐标未被改写。

## DEC-002：桌面最低支持线为 1280×720

- 状态：已批准
- 日期：2026-08-31
- 最终决定：1280×720 至 3840×2160 为完整大屏支持范围；更窄容器进入紧凑降级，保证操作可达但不承诺完整桌面编排。

## DEC-003：部件层改为实际容器满铺

- 状态：已批准，取代 DEC-001 中的“等比安全画布”部分
- 日期：2026-09-01
- 决策人：用户
- 背景：实际地图部件编辑器为宽屏、低高度容器，等比 `fit` 会按高度缩放并水平居中，导致部件层左右留白、视觉上整体缩小。
- 最终决定：Cesium 继续原生铺满；部件画布改为铺满顶部栏下方全部可用宽高。GridStack 保留逻辑 `x/y/w/h`，列宽由实际宽度分配，行高由实际高度分配，不使用 CSS `transform` 拉伸部件内容。
- Risks：同一部件在不同比例屏幕上的宽高比会变化，图表和复杂内容必须依赖自身响应式布局；极端宽屏下中间空白区域会随列宽增加。
- Impact：只改变运行页和编辑器的部件画布几何尺寸；不修改模板逻辑坐标、Cesium 拾取、视频身份、API、数据库或部署。
- Options：保留等比安全画布会继续出现截图中的左右留白；整页 CSS 缩放会影响清晰度和交互，仍不采用。
- 回退：把画布宽高恢复为按 1920×1080 比例计算并居中即可；模板布局数据无需迁移。

## DEC-004：运行页与编辑器按实际占用行数统一纵向铺满

- 状态：已批准
- 日期：2026-09-01
- 决策人：用户
- 背景：用户运行页按固定 25 个设计行计算行高，而当前模板实际只占用约 21 行，导致部件集中在上方并在底部留下大片空白；编辑器期望效果是实际部件纵向铺满可用画布。
- 最终决定：模板非空时，只统计存在对应部件数据、实际会被渲染的布局项，并以其中最大的 `y + h` 作为响应式有效行数；空模板才使用持久化的 `viewport.rows`。运行页与编辑器共同调用同一解析函数，不修改任何部件的 `x/y/w/h`。
- Risks：原本有意预留在最后一个部件下方的空设计行不再表现为空白；如未来需要固定留白，应增加明确的画布留白配置，而不是依赖未占用网格行。
- Impact：只影响 GridStack 纵向行高计算；Dashboard 配置、API、数据库、设备点位和视频链路均不变化。
- 回退：恢复直接使用 `viewport.rows` 计算行高即可；模板数据无需迁移。
