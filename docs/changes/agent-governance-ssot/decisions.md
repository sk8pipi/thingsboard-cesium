# 任务决策记录

## DEC-001：以分类事实源代替单一万能文档

- 状态：已批准
- 日期：2026-08-08
- 决策人：用户
- 背景：项目已有事实优先级和任务模板，但缺少实际任务档案、全局活动登记和机械一致性检查。
- 最终决定：按事实类别分别指定权威落点；协作状态必须持久化到仓库文件，聊天和 Agent 摘要仅作为线索。
- 选择理由：代码、架构、任务状态和验证结果具有不同生命周期，强行合并到一个文件会造成高频冲突和事实混淆。
- 备选方案：仅依赖聊天交接；使用单个中央 Markdown 保存全部状态；引入外部任务平台。
- Risks：文件可能未及时更新；规范和执行配置可能漂移。
- Impact：所有多 Agent、中大型、高风险或需要上下文切换的任务必须建立任务档案。
- Options：当前选择仓库内 JSON 登记、Markdown 档案和 PowerShell 校验，不引入外部依赖。
- 兼容与迁移影响：现有小型单 Agent 任务可继续使用快速流程；符合建档条件的新任务开始强制使用。
- 回退方案：删除新增登记和校验入口即可回到原有纯文档流程，不影响业务代码。
- 关联文件或接口：`docs/changes/active-tasks.json`、`docs/changes/<任务编号>/`。
- 替代的旧决策：无。

## DEC-002：中央登记单写入，任务档案长期保留

- 状态：已批准
- 日期：2026-08-08
- 决策人：用户
- 背景：多个顶层任务仅维护各自 `delivery.md` 时，无法发现文件范围和共享资源冲突。
- 最终决定：活动任务写入中央登记；由当前中央主 Agent 串行维护。任务完成或取消后从活动登记移除，但任务目录继续保留。
- 选择理由：兼顾全局冲突检查和长期可审计性，同时避免多个实现 Agent 修改中央文件。
- 备选方案：每个任务自行登记；使用外部数据库锁；允许所有 Agent 修改中央登记。
- Risks：跨 worktree 的未提交状态不能自然同步；异常退出可能留下过期登记。
- Impact：启动、切换和结束受管任务时都必须更新中央登记并运行校验。
- Options：当前采用人工单写入加脚本校验；未来可在确认 CI/Git Hook 环境后增加自动门禁。
- 兼容与迁移影响：无业务兼容影响。
- 回退方案：停止使用中央登记，仍可保留单任务档案。
- 关联文件或接口：`docs/changes/active-tasks.json`。
- 替代的旧决策：无。

## DEC-003：协作文档为规范源，Codex TOML 为执行投影

- 状态：已批准
- 日期：2026-08-08
- 决策人：用户
- 背景：角色权限同时出现在协作文档和 `.codex/agents/*.toml`，存在双写漂移风险。
- 最终决定：`docs/ai/multi-agent-development.md` 定义规范，`.codex/agents/*.toml` 是运行时执行投影；二者通过校验脚本检查关键约束一致性。
- 选择理由：文档适合记录理由和流程，TOML 适合被 Codex 执行，二者不能互相替代。
- 备选方案：只保留文档；只保留 TOML；引入代码生成器。
- Risks：文本校验只能检查关键不变量，不能证明全部自然语言语义完全相同。
- Impact：修改角色权限时必须同时更新规范、执行投影和相关校验。
- Options：当前采用轻量文本检查；未来角色规则复杂后再评估机器可读清单和生成机制。
- 兼容与迁移影响：保持现有四类 Agent 及其权限不变。
- 回退方案：移除校验规则，恢复人工审查。
- 关联文件或接口：`docs/ai/multi-agent-development.md`、`.codex/agents/*.toml`。
- 替代的旧决策：无。
